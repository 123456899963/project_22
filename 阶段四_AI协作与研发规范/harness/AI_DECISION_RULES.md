| 项 | 内容 |
|---|---|

---

## 1 三条总则

1. **规格优先**：文档已写明的，照做，不发挥；文档没写的，先问，不补。
2. **证据优先**：进度只认可复核证据（文件、接口响应、命令输出、测试结果）；未执行不得记通过。
3. **最小改动**：只改达成当前任务所必需的部分；不顺手重构、不顺手扩功能。

---

## 2 风险分级与授权

### 2.1 可直接执行（无需询问）

| 类型 | 判据 | 例子 |
|---|---|---|
| 规格已明确的小功能 | 对应 PRD 条款 + API 路径 + 表字段均已存在 | 按 API_CONTRACT 实现 `GET /teas` 的 8 维筛选 |
| 非架构性 Bug 修复 | 根因明确、改动局限在单模块 | 分页 `hasMore` 计算错误；空态未渲染 |
| 已定契约的接口 | openapi.yaml 已有 operationId | 补全 api 路由/service |
| 已定样式的页面骨架 | PAGE_SPECS + DESIGN_SYSTEM 已写 | 按页面清单落路由与组件 |
| 文档同步 | 代码已变更，回写文档 | 补 build-log、更新 DATA_MODEL 字段说明 |
| 测试补齐 | 已有行为，补断言 | 给状态机加非法迁移用例 |

前提：改动不触碰 §2.2 任一红线；若执行中发现需要触碰，立即停下转入提问。

### 2.2 必须提问并获确认（不得自行决定）

| # | 类型 | 为什么要问 |
|---|---|---|
| 1 | 需求歧义 / 文档自相矛盾 | 决定业务结果，不能替业务方拍板 |
| 2 | 新增或修改表结构、索引、约束 | 影响迁移与历史数据 |
| 3 | 修改架构、分层、模块边界 | 影响全局可维护性 |
| 4 | 修改鉴权、角色、权限矩阵 | 安全边界，错一次就是越权 |
| 5 | 修改已确认的业务规则（上限、时限、状态机） | 与 PRD 冲突，需业务确认 |
| 6 | 不可逆操作（物理删除、批量清洗、强制迁移） | 无法回退 |
| 7 | 引入 TECH_STACK 之外的依赖或服务 | 扩大运维面 |
| 8 | 开放 V1 边界外的功能（价格、支付、关注、识图等） | 范围蔓延 |

提问格式要求：

```
【待确认】问题一句话
- 背景：引用的文档与行号
- 冲突/缺口：具体哪里不一致
- 方案 A / B（各含优点、代价）
- 我的建议：A，理由一句话
- 不确认的后果：会阻塞哪些任务
```

一次最多问 3 个最关键问题；其余记录到"待确认清单"，不阻塞当前可推进部分。

### 2.3 必须停止（不提问、不继续）

| 场景 | 动作 |
|---|---|
| 即将执行不可逆数据操作且无备份 | 停止，说明风险，等待明确指令 |
| 需要绕过权限、放宽校验才能"通过" | 停止，报告，不得绕过 |
| 需要删除测试用例才能"变绿" | 停止，报告真实失败原因 |
| 发现文档与代码存在根本冲突且无法局部修复 | 停止，输出冲突清单与建议方案 |
| 连续两次修复引入新失败 | 停止，回到问题定义，不继续试错 |
| 用户明确要求超出当前阶段（如直接进阶段六） | 停止，确认后再动 |

## 3 提问边界

### 3.1 应当提问

- 业务规则缺失或与 PRD 冲突（如"导入是否全部校验通过才允许"）。
- 同一字段两种口径（如年份区间按自然年还是按批次）。
- 权限矩阵未覆盖的新接口。
- 错误码不够用，需要新增域或三位码。
- 页面上出现 PRD 未定义的入口或字段。

### 3.2 不应提问（自主决定）

- 代码风格、命名、目录内文件位置（按 DEVELOPMENT_GUIDE）。
- 已登记错误码在既有接口上的复用。
- 单元测试的组织方式、断言写法。
- 日志级别、异常包装方式。
- 前端组件内布局细节（在 DESIGN_SYSTEM token 范围内）。
- 已明确规格下的实现顺序。

判断口诀：**问"业务要什么"，不问"代码怎么写"**。

---

## 4 执行中的决策记录

- 每个非平凡决策写入 [build-log](../harness/build-log.md)：背景、选项、结论、代价。
- 影响架构/数据/权限的决策另立 ADR（`docs/development/ADR-xx-*.md`），编号承接 ARCHITECTURE §11 的 ADR-01～09。
- 决策一旦记录，后续实现不得静默偏离；偏离必须新增记录并注明原因。

---

## 5 进度与证据规则

| 声明 | 需要的证据 |
|---|---|
| "接口已实现" | 路由存在 + service 逻辑 + （可运行则）真实响应 |
| "测试通过" | 命令 + 通过数/失败数原始输出 |
| "页面可用" | 路由可进入 + 关键交互可完成（截图或浏览器实测） |
| "迁移已执行" | 迁移脚本版本号 + 执行日志 |
| "已修复" | 复现步骤 + 修复前后对比 |

禁止表述："应该没问题""基本可用""理论上通过""已优化"。

---

## 6 上下文与范围控制

1. 单轮只推进一个可验收目标；跨轮任务先写入 PLANS.md 再执行。
2. 发现任务外缺陷：记录到 build-log 的"发现但未修"清单，不擅自扩大改动。
3. 需要读大量文件时先列清单再读，避免无目标扫描。
4. 每次交付附"已做 / 未做 / 待确认"三段，未做项不得含糊。

---

## 7 本轮验收

1. 三类授权（可直接执行 / 必须确认 / 必须停止）边界清晰、可判定。
2. 提问与不提问的边界有口诀与示例，能覆盖阶段五高频场景。
3. 证据规则可反向约束"虚报进度"。
4. 与 AGENTS.md、DEVELOPMENT_GUIDE 无冲突。
