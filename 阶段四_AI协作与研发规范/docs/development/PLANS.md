## 1 交付范围与口径

### 1.1 本阶段目标

在 `backend/`、`frontend/`、`deploy/` 落地可运行的 V1 工程：

- 后端：M01–M10 核心接口按 API_CONTRACT 实现；M11 横切能力可用（Envelope、错误码、traceId、JWT、限流骨架、审计写入、StorageService）。
- 前端：38 条路由全部可进入；P0 页面功能闭环（首页、列表、详情、搜索、自查、登录、个人中心、收藏、历史、对比、投稿、后台工作台/茶品/投稿/评论/举报/审计/配置）。
- 部署：`docker-compose.yml`、`nginx.conf`、`.env.example`、备份脚本。

### 1.2 环境限制（影响验收口径）

| 限制 | 影响 | 应对 |
|---|---|---|
| 本机无 JDK 17 / Maven | 后端无法编译、无法起服务 | 代码按可编译标准手写；R7 明确标注"未编译验证"，列出待执行命令 |
| 本机 MySQL 客户端 5.7 | 无法执行 MySQL 8 DDL | `init.sql` 与 Flyway 脚本做静态校验；容器环境待执行 |
| Node/npm 可用 | 前端可 `npm install`/`build`（依赖网络） | 若安装失败，标注"未构建验证"，不只写"已通过" |
| 微信开放平台资质缺失 | 真实扫码登录不可用 | 提供 `dev` mock 登录开关，生产必须走真实 `code2Session` |

### 1.3 完成定义（DoD）

单个任务完成 = 任务卡四项齐全 + 代码落盘 + 自检清单 10 项通过 + 证据写入 build-log + 未验证项显式标注。

## 2 任务分解

### 2.1 优先级定义

## 5 风险与应对

| # | 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|---|
| 1 | 无 JDK/Maven，后端首次构建失败 | 高 | 交付可信度 | 严格按 Spring Boot 3.2 API 手写；R7 标注未验证并给命令 |
| 2 | 依赖下载失败（npm） | 中 | 前端无法构建 | 锁版本、最小依赖；失败则标注 |
| 3 | 38 页全量功能超出单阶段容量 | 高 | 完成度不足 | P0 闭环、P1 主干、P2 骨架；R7 如实分级 |
| 4 | 微信联调缺失 | 高 | 登录链路未真实验证 | dev mock + 生产开关；文档标注 |
| 5 | MySQL 8 生成列/唯一索引未实跑 | 中 | 迁移失败 | 静态校验 + 容器环境待执行清单 |
| 6 | 文档口径冲突复发 | 低 | 返工 | AGENTS §1.1 裁决顺序 + build-log 登记 |
