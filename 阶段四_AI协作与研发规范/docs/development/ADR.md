## ADR-01 单体分层，不拆微服务

- **背景**：100 并发、46 款茶品、单机 Compose、单人运维。
- **决策**：Spring Boot 单进程，按 M01–M11 包内分层。
- **备选**：微服务（服务治理与独立扩缩容）→ 否决：部署、联调、监控成本远超收益。
- **代价**：模块边界只能靠包结构、评审与自检清单维持。
- **复核**：并发 >1000 或团队 >5 人并行开发时重评。

## ADR-02 前后台同一 SPA，路由前缀隔离

- **背景**：38 页中前台 20、后台 18，共用请求层与组件。
- **决策**：同一 Vue 应用，`/` 与 `/admin` 两套布局与守卫。
- **备选**：两个独立应用 → 否决：重复维护请求层、类型与登录态。
- **代价**：构建需按路由分包；守卫写错会导致后台入口暴露（故权限仍以服务端为准）。
- **复核**：后台体积或权限模型显著复杂化时拆分。

## ADR-03 JWT access + Redis refresh

- **背景**：仅微信授权、无密码、多设备在线、需主动失效。
- **决策**：access 2h 无状态；refresh 7d 存 Redis，注销即拉黑。
- **备选**：纯 Session → 否决：横向扩容需共享会话且失效粒度粗；纯 JWT 长令牌 → 否决：无法主动失效。
- **代价**：依赖 Redis；刷新链路有状态。
- **复核**：Redis 不可用时仍可凭 access 校验（已纳入降级）。

## ADR-04 本地磁盘 + StorageService 抽象

- **背景**：不启用商用 CDN；图片需可追溯来源与授权。
- **决策**：`/data/mm/uploads` + Nginx `/uploads/` 直出；接口 `StorageService`。
- **备选**：对象存储 → 否决：V1 无 CDN 且运维面扩大；存库 BLOB → 否决：备份与直出性能差。
- **代价**：单机磁盘容量与备份压力；需孤儿文件清理任务。
- **复核**：图片量 >10 万或需多机部署时切换实现。

## ADR-05 MySQL 结构化查询，不引 ES

- **背景**：46 款茶品，检索仅结构化字段精确匹配（R-11、R-12）。
- **决策**：MySQL + 索引 + `LIKE`/拼音字段；无全文引擎。
- **备选**：Elasticsearch → 否决：数据规模不需要，增加运维与一致性负担。
- **代价**：相关度排序能力有限；扩展需重构。
- **复核**：茶品量 >5000 或需模糊语义检索。

## ADR-06 站内消息落库，不接推送

- **背景**：V1 只要求站内可见、保留 180 天、不可删除（R-52）。
- **决策**：`message` 表 + 未读计数缓存；不接短信/微信模板消息。
- **代价**：触达弱，用户需主动查看。
- **复核**：运营提出触达诉求时进二期评估。

## ADR-07 事务内事件 + 提交后处理 + 补偿表

- **背景**：审核通过需联动通知、缓存、缩略图、统计，跨模块但不可强耦合。
- **决策**：领域事件随业务事务登记，`AFTER_COMMIT` 处理；失败写 `task_retry`，最多 5 次并告警。
- **代价**：需维护补偿任务与告警；最终一致存在短窗口。
- **复核**：出现必须强一致的跨模块写操作时改为同事务同步调用。

## ADR-08 茶品"线上版本 + 修订草稿"双版本

- **背景**：已上架条目编辑不得立即影响前台；修订需留痕（R-45、PRD §10.1）。
- **决策**：`tea` 保存线上字段与 `published_version`；编辑写 `tea_revision` 草稿，审核通过后切换发布版本。
- **代价**：查询需区分线上版本与草稿；待审唯一约束需生成列兜底。
- **复核**：若引入"定时发布"，需扩展版本状态。

## ADR-09 缩略图异步生成

- **背景**：上传响应需快；单图 ≤5MB、需 4:3 展示。
- **决策**：上传即落原图，异步生成 640×480 与 1600×1200；失败进补偿任务。
- **代价**：列表首次可能短暂缺图，回退原图 + 占位。
- **复核**：图片处理耗时影响上传体验时改为同步 + 限流。

## ADR-10 对比篮服务端持久化

- **背景**：PRD §12.4 要求 Web 与小程序双端一致；Pinia 仅能覆盖单端。
- **决策**：`user_compare` 按用户持久化，上限 3 款；前端 Pinia 只做缓存。
- **备选**：纯前端 localStorage → 否决：双端不一致、清缓存即丢失。
- **代价**：每次对比操作多一次写库；需处理并发加入冲突（409）。
- **复核**：对比篮若扩展为"方案集"需重设模型。

## ADR-11 审核动作统一编排，归属模块执行状态迁移

- **背景**：茶品/投稿/评论三类审核动作相似，但状态归属不同模块。
- **决策**：M08 只做审核队列、动作编排与留痕；状态迁移由 M02/M06/M07 各自执行，M08 不直接写状态列。
- **代价**：跨模块调用增多，需保证同一事务或事件一致性。
- **复核**：若审核流程出现强顺序依赖（多级审核），需引入流程引擎或状态表。

## ADR-12 上游文档冲突以 TECH_STACK 与 PRD 为准

- **背景**：PAGE_SPECS §3.3 残留"共用 Flask/Python 接口"，与 TECH_STACK 的 Java 选型冲突。
- **决策**：技术栈以 TECH_STACK 为准，业务规则以 PRD 条款文字为准；不改上游历史文档，差异登记于 build-log 与 ARCHITECTURE §12。
- **代价**：新成员可能读到过期表述，需在 AGENTS.md §1.1 明确裁决顺序。
- **复核**：PAGE_SPECS 下次修订时消除该冲突。
