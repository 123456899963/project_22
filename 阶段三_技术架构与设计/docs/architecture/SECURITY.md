## 1 安全目标与保护对象

### 1.1 目标

| 目标 | 可验证结论 |
|---|---|
| 身份可信 | 只有微信授权换取的 openid 能建立账号；令牌不可伪造、可撤销 |
| 权限不越界 | 游客 / 用户 / 管理员 / 超管四类角色的每个接口均有服务端校验 |
| 数据不泄露 | openid、令牌、磁盘路径、内部快照不出现在接口响应、前端包与日志 |
| 内容可追溯 | 审核、上下架、处罚、白名单、配置变更全部留痕且不可篡改 |
| 上传不可利用 | 仅 jpg/png/webp，经解码重编码后落盘，不可执行、不可穿越目录 |
| 滥用可抑制 | 登录、投稿、评论、举报、上传均有频次约束，超限返回 `MM-SYS-002` |
| 可恢复 | 每日备份保留 7 份，季度恢复演练；审计与业务数据分离保留 180 天 |

### 1.2 保护对象

| 资产 | 位置 | 机密性 | 完整性 | 可用性 |
|---|---|---|---|---|
| openid 与账号映射 | `user_identity` | 高 | 高 | 高 |
| 昵称、头像、内容归属 | `user_profile`、评论、投稿 | 中 | 中 | 中 |
| 茶品与图片 | `tea`、`media_image`、上传目录 | 低（公开） | 高 | 高 |
| 审核与治理记录 | `submission`、`report`、`sanction`、`appeal`、`audit_log` | 高 | 高 | 中 |
| 系统配置 | `system_config`、环境变量 | 高 | 高 | 高 |
| 会话与限流数据 | Redis | 高 | 中 | 高 |
| 备份包 | 异机备份目录 | 高 | 高 | 中 |

### 1.3 信任边界

```
浏览器 / 小程序 ──HTTPS──> Nginx ──内网──> Spring Boot ──> MySQL 8 / Redis 7 / 上传目录
                                   │
                                   └──HTTPS──> 微信开放平台（code2Session）
```

- 浏览器、小程序、请求头、上传文件、Excel 导入文件全部视为不可信输入。
- Nginx 只做 TLS、静态资源、反向代理与基础限流；业务鉴权一律在后端完成。
- 前端路由守卫仅改善体验，不构成安全边界（TECH_STACK §6）。
- 微信开放平台返回值仅信任 `openid` 与 `errcode`，其余字段不落库。

### 1.4 V1 明确不做

- 不引入 WAF、商用风控、内容安全第三方 API、短信二次验证。
- 不做支付、商品、第三方账号体系，因此无支付回调签名与资金对账风险面。
- 不做等保测评与渗透测试报告；安全测试按本文件 §14 自检清单执行。

## 2 认证与会话

### 2.1 微信授权链路

| 环节 | 安全要求 |
|---|---|
| 二维码 | `POST /auth/qrcode` 生成一次性 `ticket` 与 `state`；`state` 5 分钟过期且仅可使用一次 |
| 轮询 | `GET /auth/qrcode/{ticket}` 只返回 `pending/scanned/confirmed/expired`，不返回 openid 或令牌 |
| 回调 | `POST /auth/wechat/callback` 校验 `state` 与 `ticket` 绑定关系；过期、重放、来源不符一律 `MM-AUTH-005` |
| 换取 | `code2Session` 仅在服务端调用；`AppSecret` 只读环境变量 `MM_WECHAT_SECRET` |
| 建号 | 以 openid 唯一键幂等建号；并发首登冲突按唯一索引捕获后重查，不产生双账号 |
| 失败 | 微信返回失败时降级游客态，返回 `MM-AUTH-006`，不自动建号、不猜测身份（PRD E11） |
| 已注销 | 注销完成即解绑 openid；同一微信再次授权创建新账号，不恢复旧数据（PRD E14） |

### 2.2 令牌设计

| 项 | 规则 |
|---|---|
| access token | JWT，有效期 2 小时；载荷仅 `sub`（用户 ID）、`role`、`deviceId`、`iat`、`exp`、`jti` |
| 签名 | HS256，密钥 `MM_JWT_SECRET` ≥256 位随机值，只从环境变量注入；预留 `kid` 以支持轮换 |
| refresh token | 256 位随机不透明串，存 Redis `mm:{env}:auth:refresh:{sha256(token)}`，有效期 7 天 |
| 刷新 | 每次刷新轮换 refresh token；旧 token 立即删除；检测到已删除 token 再次使用则撤销该设备全部会话 |
| 注销 | `POST /auth/logout` 删除 refresh 记录，并将 access `jti` 写入黑名单至 `exp` |
| 多设备 | 每设备独立 `deviceId` 与 refresh 记录；注销仅影响当前设备（PRD §3.3 允许多设备在线） |
| 传输 | Web 端 refresh token 由服务端写入 `HttpOnly; Secure; SameSite=Lax` Cookie；响应体 `refreshToken` 仅小程序端使用，Web 前端忽略 |
| 禁止 | 不把令牌写入 URL、日志、localStorage 长期存储；access token 仅存内存（Pinia） |

### 2.3 账号状态与处罚

| 状态 | 认证行为 |
|---|---|
| `active` | 正常签发与校验 |
| `deleting` | 允许登录与浏览；评论、投稿、纠错、新增收藏返回 `MM-AUTH-004`（PRD §6.11） |
| `deleted` | 不可登录；refresh 记录已清除 |
| 禁言 | 可登录可浏览；评论、投稿在处罚期内返回 `MM-AUTH-004` |
| 封禁 | 拒绝登录与全部写操作；已有 access token 在下一次请求即被拒绝 |

- 处罚状态每次请求从 Redis 缓存读取（TTL ≤60 秒），处罚生效延迟不超过 60 秒；撤销处罚立即删除缓存。
- 账号状态变更全部写 `audit_log` 与 `sanction`，不物理删除处罚记录。

### 2.4 管理员身份

| 项 | 规则 |
|---|---|
| 判定 | `admin_whitelist` 中 openid 命中且 `enabled=1`；角色为 `admin` 或 `super` |
| 校验 | 每次请求同时校验 JWT `role` 与数据库/缓存白名单；白名单移除后 5 分钟内失效 |
| 入口 | 后台接口统一前缀 `/api/v1/admin/**`；前台不暴露管理端入口 |
| 超管保护 | 移除或降级超管前统计剩余超管数，少于 1 名返回 `MM-GOV-004` |
| 自处置 | 管理员不可禁言/封禁自己，不可移除自己的超管身份（`MM-GOV-003`） |
| 初始超管 | 仅由部署环境变量 `MM_SUPER_ADMIN_OPENID` 写入，不提供页面创建 |

## 3 授权与访问控制

### 3.1 模型

采用 **RBAC + 资源归属** 双重校验：

1. 路由级：拦截器按 `API_CONTRACT §6` 权限矩阵校验角色，未登录返回 `MM-AUTH-001`，角色不足返回 `MM-AUTH-003`。
2. 服务级：对 `/me/**`、投稿、评论删除、举报申诉等资源，必须附加 `owner_user_id = 当前用户` 条件。
3. 数据级：管理端按职责读取；审计日志普通管理员只读；导出仅超管。

### 3.2 资源归属规则

| 资源 | 规则 | 越权返回 |
|---|---|---|
| `/me/favorites`、`/me/history`、`/me/compare`、`/me/messages` | 仅当前用户 | 403 `MM-AUTH-003` |
| `/me/submissions/{id}`、`/preview` | 仅作者；管理员通过 `/admin/submissions/{id}` 访问 | 404（避免枚举他人草稿） |
| `DELETE /me/comments/{id}` | 仅作者；管理员走审核接口 | 404 |
| `POST /reports/{id}/appeal` | 仅被处理方 | 403 |
| `/admin/audit-logs` | 管理员只读、不可删改；`export=true` 仅超管 | 403 |
| `/admin/admins`、`/admin/settings`、`/admin/appeals/*` | 仅超管 | 403 |

- 私有资源不存在与无权限统一返回 404，避免通过状态码枚举他人数据；管理端越权返回 403。
- 所有列表查询强制拼接归属条件，禁止先查全量再在内存过滤。

### 3.3 前端边界

- 路由守卫只用于跳转登录页与隐藏入口；即使绕过，后端仍按 §3.1 拒绝。
- 后台与前台同 SPA 但路由分离：`/admin/**` 需 `role ∈ {admin, super}`；前台登录态不自动获得后台权限。
- 前端不缓存权限判定结果作为放行依据。

## 4 输入校验与输出编码

### 4.1 服务端校验

| 输入 | 规则 |
|---|---|
| 昵称 | 2～20 字；去除首尾空白；敏感词与联系方式命中即 400 |
| 评论 | 1～200 字；纯文本；店铺名、微信号、购买链接命中即 400（PRD §6.9） |
| T1 正文 | ≥300 字；纯文本，不解析 HTML/Markdown |
| T4 理由 | 20～200 字；必填 |
| 茶品字段 | 枚举白名单：茶类、亚类、等级、采摘期、器皿、图片来源；标准号按格式校验 |
| 年份 | 四位整数，范围 `1900～当前年份`；年份区间由服务端计算，忽略客户端传值 |
| 分页 | `page ≥1`、`1 ≤ size ≤50`；排序仅允许 `updated_desc/name_pinyin/grade_desc` |
| 枚举参数 | 未在白名单内的值直接 400 `MM-SYS-001`，不做模糊匹配 |

- 使用 Bean Validation 在 controller 入参处校验；业务规则（额度、查重、状态）在 service 层二次校验。
- 不接受客户端传入的角色、用户 ID、审核状态、计数、时间戳等可信字段。

### 4.2 注入防护

| 风险 | 措施 |
|---|---|
| SQL 注入 | MyBatis 一律 `#{}` 占位；禁止 `${}` 拼接；排序字段走白名单映射；XML 中不使用动态表名 |
| 越权查询 | 所有私有查询带 `user_id` 条件；不使用前端传入的 owner 参数 |
| XSS | 接口只返回 JSON；前台使用 Vue 文本插值，禁止 `v-html` 渲染用户内容；管理端同样不渲染用户 HTML |
| 开放重定向 | 登录回跳仅允许站内相对路径，拒绝 `//`、`http(s)://`、`javascript:` |
| SSRF | V1 不提供 URL 抓取、远程图片下载、Webhook，不存在服务端外呼入口 |
| Excel 公式注入 | 导入模板仅接受文本/数字；导出与回显时对以 `= + - @` 开头的单元格前置 `'` |
| 反序列化 | 不接收 Java 序列化数据；JSON 只绑定 DTO，不开放任意类型 |

### 4.3 输出与错误信息

- 统一 Envelope `{code,message,data,traceId}`；`message` 为面向用户的中文提示，不包含堆栈、SQL、类名、磁盘路径。
- 生产环境关闭 `stacktrace` 与 MyBatis SQL 日志；异常统一由全局处理器转换为 `MM-SYS-003`。
- 详情接口不返回 `openid`、`user_identity` 内部字段、`tea_revision` 原始快照、`audit_log` 内部 diff。
- 图片 URL 只返回 `/uploads/...` 站内路径，不返回绝对路径（API_CONTRACT §3.4）。

## 5 文件与媒体安全

### 5.1 上传校验

| 层 | 规则 |
|---|---|
| 扩展名 | 仅 `.jpg`、`.jpeg`、`.png`、`.webp` |
| MIME | 仅 `image/jpeg`、`image/png`、`image/webp` |
| 文件头 | 读取魔数校验，三者不一致即拒绝 `MM-MEDIA-001` |
| 大小 | 单图 ≤5MB，超限 `MM-MEDIA-002`（PRD §12.1） |
| 像素 | 解码后总像素 ≤4000 万，宽高均 ≤10000，防解码炸弹 |
| 重编码 | 使用 ImageIO 解码后重新编码为 jpg/webp，剥离 EXIF、ICC 与附加段 |
| 命名 | 服务端生成 UUID 文件名；原始文件名不落盘、不回显 |

### 5.2 存储与访问

- 上传目录 `/data/mm/uploads` 不在 Web 根目录内，Nginx 以 `/uploads/` 只读映射；目录禁止脚本执行。
- 路径由服务端按 `tea/{teaId}/{type}-{seq}.{ext}` 生成，任何请求参数不得拼接真实路径；拒绝 `..`、绝对路径与空字节。
- 临时文件在请求结束或失败时删除；孤儿文件由每日清理任务按数据库引用比对后删除。
- 响应头对 `/uploads/` 附加 `X-Content-Type-Options: nosniff` 与 `Content-Disposition: inline`。

### 5.3 授权与可见性

| 场景 | 规则 |
|---|---|
| 官方图鉴 | 仅管理员上传；必须录入来源类型、权利人、授权范围、期限、凭证编号 |
| 用户投稿图 T3 | 存 `submission_image`，审核通过前不可公开访问；作者必须勾选书面授权 |
| 用户实拍 | 仅审核通过后进入“用户实拍”相册，展示授权状态 |
| 缺凭证 | 只允许保存草稿，提交审核返回 `MM-MEDIA-003` / `MM-CATALOG-003` |
| 删除 | 逻辑删除记录保留，文件由清理任务延迟删除，保留期 7 天以便申诉复核 |

- 演示图 `docs/content/demo-images/` 不得进入上传目录或生产包（TECH_STACK §5）。

## 6 数据保护与隐私

### 6.1 数据分级与最小化

| 级别 | 数据 | 处理 |
|---|---|---|
| 公开 | 茶品字段、官方图片、已发布评论/投稿 | 可匿名访问 |
| 内部 | 审核队列、导入任务、系统配置 | 仅管理员 |
| 个人 | 昵称、头像、收藏、历史、对比、投稿、消息 | 仅本人与职责管理员 |
| 敏感 | openid、令牌、授权凭证、举报人身份、审计日志 | 严格按角色，禁止出接口与日志 |

- 仅收集微信 openid、昵称、头像与用户主动提交的内容；不收集手机号、定位、通讯录（PRD §13）。
- 身份与资料分表：openid 只在 `user_identity`；展示字段在 `user_profile`，降低联表泄露面。

### 6.2 注销与匿名化

1. 申请注销写 `account_deletion_request`，进入 7 天冷静期；期间可撤销、可浏览，禁止评论/投稿/纠错/新增收藏。
2. 到期任务解绑 openid、清空昵称与头像、标记 `deleted`；评论与投稿保留但作者展示为“已注销用户”。
3. 审核留痕、处罚、举报处理记录不删除，仅去除个人标识。
4. 注销后同一微信再次授权创建新账号，不关联旧数据（PRD E14）。

### 6.3 日志与保留

| 项 | 规则 |
|---|---|
| 应用日志 | JSON 行日志，含 `traceId`、`userId`（内部 ID）、路径、状态码、耗时；不含令牌、openid、请求体 |
| 访问日志 | Nginx 记录 IP、UA、路径；不记录 Authorization 与查询串中的敏感值 |
| 审计日志 | 保留 180 天，仅追加；到期归档后删除（PRD §12.3） |
| 站内消息 | 保留 180 天后清理（PRD §6.12） |
| 备份 | 每日 1 份，保留 7 份；加密存放于异机目录 |
| 申诉与处罚 | 不物理删除，保留至审计周期结束 |

- 举报人身份仅管理员可见；对外与对被举报方均不展示举报人信息。
- 管理员导出审计日志必须记录“导出”动作本身，且仅超管可执行。

## 7 传输、会话与浏览器安全

| 项 | 规则 |
|---|---|
| TLS | 全站 HTTPS，TLS 1.2+；HTTP 301 跳转 HTTPS；启用 HSTS（`max-age=31536000`） |
| 安全头 | `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: strict-origin-when-cross-origin`、`Permissions-Policy: camera=(self), microphone=()` |
| CSP | `default-src 'self'; img-src 'self' data:; script-src 'self'; style-src 'self' 'unsafe-inline'; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'` |
| CORS | 生产同源经 Nginx 代理，不开放跨域；开发仅允许 `http://localhost:5173` |
| Cookie | refresh cookie：`HttpOnly; Secure; SameSite=Lax; Path=/api/v1/auth` |
| CSRF | 业务接口使用 `Authorization: Bearer`，不依赖 Cookie；刷新接口校验 `Origin` 并仅接受 POST |
| 缓存 | 含个人数据的接口响应 `Cache-Control: no-store`；公开内容允许 ETag 协商缓存 |

- V1 不接入商用 CDN；静态资源与上传目录同源提供，避免第三方域名带来的 Cookie 与内容风险。

## 8 限流与反滥用

| 场景 | 维度 | 阈值（建议值） | 超限行为 |
|---|---|---|---|
| 生成登录二维码 | IP | 20 次/分钟 | 429 `MM-SYS-002` |
| 扫码轮询 | ticket | 1 次/秒 | 429，前端退避 |
| 微信回调 | IP | 10 次/分钟 | 429 |
| 刷新令牌 | refresh token | 1 次/10 秒 | 429 |
| 关键词搜索 | IP | 30 次/分钟 | 429 |
| 识茶自查 | IP | 20 次/分钟 | 429 |
| 发布评论 | 用户 | 5 条/分钟 | 429 |
| 提交投稿 | 用户 | 3 条/日（PRD §6.10） | 403 `MM-SUB-001` |
| 举报 | 用户 + 对象 | 同一对象 24 小时内 1 次 | 409 `MM-GOV-001` |
| 图片上传 | 用户 | 20 张/小时 | 429 |
| 管理端写操作 | 管理员 | 不设硬限流，全部审计 | — |

- 计数使用 Redis `INCR` + 过期键，键格式 `mm:{env}:rate:{scope}:{key}`。
- Redis 不可用时：登录、刷新、投稿、评论等写接口 **fail-closed**（返回 503 `MM-SYS-003`）；公开读接口放行，仅记录告警。
- 反垃圾：T1/T3/T4 按“茶名 + 茶类 + 亚类 + 类型”查重；命中返回 `MM-SUB-002` 并引导改用纠错/补图（PRD E9）。

## 9 内容与合规安全

| 风险 | 措施 |
|---|---|
| 医疗功效表述 | 详情与投稿统一展示医疗免责声明；审核清单检查“治疗、抗癌、减肥、降血压”等功效词 |
| 导流与广告 | 评论、投稿、昵称禁止店铺名、微信号、二维码、购买链接；命中即拒 |
| 版权侵权 | 图片必须来源与授权；举报入口覆盖详情图、评论、用户实拍；核实后下架并留痕（PRD E6） |
| 争议产区 | 并列呈现，不做单一裁定（PRD E8） |
| 违法违规内容 | V1 依赖人工审核；不接入第三方审核 API，审核员按清单处置并填写理由 |
| 未成年人 | V1 不设年龄门槛；不收集额外个人信息，协议中提示监护人同意（建议，待确认） |

- 所有驳回、下架、处罚、申诉复核必须填写理由；理由对作者可见，对举报人可见处理结果。

## 10 审计与监控

### 10.1 审计范围

| 动作 | 记录表 | 关键字段 |
|---|---|---|
| 茶品提交/审核/上下架 | `audit_log` | operator、action、objectId、reason、before/after 摘要、traceId |
| 投稿审核、评论审核 | `audit_log` | decision、reason、objectId |
| 举报处理、申诉复核 | `audit_log` + `report`/`appeal` | decision、resultNote、action |
| 禁言/封禁/解除 | `audit_log` + `sanction` | type、reason、endAt |
| 白名单增删 | `audit_log` | openid（脱敏展示）、role |
| 系统配置变更 | `audit_log` + `system_config_log` | key、oldValue、newValue |
| 审计导出 | `audit_log` | export=true、范围、操作人 |

- `audit_log` 仅插入；应用数据库账号无 `UPDATE/DELETE` 权限；后台页面只读。
- 记录操作人内部 ID、角色、IP、UA、`traceId` 与时间；不记录完整请求体与令牌。

### 10.2 告警

| 事件 | 阈值 | 动作 |
|---|---|---|
| 连续 401/403 | 单 IP 5 分钟内 20 次 | 记录安全日志，必要时临时封禁 IP |
| 登录回调失败 | 单 IP 5 分钟内 10 次 | 告警并限流 |
| 上传拒绝率 | 单用户 1 小时内 10 次 | 告警 |
| 审计写入失败 | 任意 1 次 | 立即告警，业务写操作回滚 |
| 备份失败 | 任意 1 次 | 写入站内系统通知并告警（TECH_STACK §8） |

- 日志按天滚动保留 180 天；安全事件单独标记，便于追溯。

## 11 密钥与配置管理

| 密钥/配置 | 来源 | 轮换 | 禁止 |
|---|---|---|---|
| `MM_DB_PASSWORD` | 环境变量 / Compose secret | 泄露或年度 | 入库、入仓、入前端包 |
| `MM_REDIS_PASSWORD` | 环境变量 | 同上 | 同上 |
| `MM_JWT_SECRET` | 环境变量，≥256 位 | 年度或泄露 | 硬编码、日志输出 |
| `MM_WECHAT_APPID/SECRET` | 环境变量 | 按微信要求 | 前端可见 |
| `MM_SUPER_ADMIN_OPENID` | 部署配置 | 超管变更时 | 页面可编辑 |

- 仓库提交 `.env.example` 仅含键名与占位符；`.env`、`application-prod.yml` 明文口令不得入库。
- 数据库账号最小权限：应用账号仅业务库 DML；Flyway 使用独立迁移账号；监控账号只读。
- 上传目录、备份目录权限仅服务进程与运维账号可读写；备份包加密后异机存放。
- 系统配置接口只返回可编辑的非敏感项；敏感配置不提供读写接口。

## 13 供应链与部署安全

- 依赖版本锁定（`pom.xml`、`package-lock.json`），构建使用锁定版本；不引入来源不明的包。
- 生产构建排除 `devDependencies`、演示图、测试数据与本地配置。
- Docker 镜像使用官方基础镜像；容器以非 root 用户运行；仅暴露 Nginx 端口。
- 部署脚本不包含明文密钥；发布前执行 Flyway 校验，禁止手改线上表结构（TECH_STACK §4）。
- 生产关闭 Actuator 敏感端点，仅暴露 `health`；Swagger/OpenAPI 文档不在生产公开。

## 14 安全测试与验收

安全用例统一在 [TEST_PLAN](../testing/TEST_PLAN.md) §7 登记，本节只列验收门槛。

| # | 验收项 | 通过标准 |
|---|---|---|
| 1 | 认证 | 伪造/过期/篡改 JWT 全部 401；refresh 重放会撤销设备会话 |
| 2 | 越权 | 游客访问 `/me/**` 401；用户访问他人资源 404；用户访问 `/admin/**` 403 |
| 3 | 管理员 | 非白名单 openid 即使角色字段为 admin 也被拒绝；移除白名单 5 分钟内失效 |
| 4 | 上传 | 改扩展名、改 MIME、伪造魔数、超大文件、路径穿越全部被拒 |
| 5 | 注入 | 搜索、筛选、排序、导入字段无 SQL 注入；用户内容不产生 XSS |
| 6 | 限流 | 投稿第 4 条 403；重复举报 409；超频接口 429 |
| 7 | 隐私 | 响应与日志中检索不到 openid、令牌、磁盘绝对路径 |
| 8 | 审计 | 审核/上下架/处罚/白名单/配置变更均有记录，且不可通过接口修改 |
| 9 | 注销 | 冷静期内写操作被拒；到期 openid 解绑、内容匿名化 |
| 10 | 备份 | 备份文件可恢复至测试库，图片引用可访问 |
