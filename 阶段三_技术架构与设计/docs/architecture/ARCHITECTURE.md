## 1 架构目标与约束

### 1.1 目标

| 质量属性 | V1 目标（来源） | 架构应对 |
|---|---|---|
| 可交付 | 38 页（前台 20 + 后台 18）一次交付 | 前后台同 SPA、按业务域分模块，页面到模块一一映射（见 MODULE_DESIGN §2） |
| 性能 | 首屏 ≤2 秒、100 并发（PRD §12.1）；接口 P95 ≤300ms（TECH_STACK §7） | 单次聚合接口 + 缩略图 + 懒加载；Redis 缓存热点；连接池 20 |
| 可用性 | ≥95%（PRD §12.2） | 单机容器 + 健康检查 + 自动重启；静态资源与接口分离 |
| 可追溯 | 审核、下架、白名单、禁言留痕 180 天（R-51） | 审计日志同事务写入；修订版本只增不改 |
| 合规 | 图片授权可追溯；演示图禁入生产 | `StorageService` 统一入口 + 来源凭证强校验 + 部署脚本排除 `docs/content/demo-images` |
| 可运维 | 单人可运维 | Docker Compose 四类进程；备份/恢复脚本；结构化日志 + traceId |

### 1.2 约束

- 部署形态为 V1 单机 Compose（TECH_STACK §6），不引入消息队列、搜索引擎、独立文件服务。
- 小程序不在本期内，但必须复用同一后端接口；接口层不得嵌入 Web 端页面结构。
- V1 边界不扩张：无价格/商品/支付/关注/私信/自动识图（PRD §2.3）。
- 前台与后台共用一套后端与一套数据库，权限在服务端判定，前端守卫仅用于体验。

```
│  /api/        → 反向代理 :8080                │
└──────────────────────────────────────────────┘
   │ 内网
   ▼
┌──────────────────────────────────────────────┐
│ Spring Boot 3.2（单进程，无状态可横向扩容）   │
│  · REST API /api/v1                            │
│  · 鉴权、限流、审计、任务调度、站内消息        │
│  · StorageService（V1 = LocalStorage）         │
└──────────────────────────────────────────────┘
   │                    │
   ▼                    ▼
┌────────────┐    ┌────────────┐
│ MySQL 8    │    │ Redis 7    │
│ 业务主数据 │    │ 会话/缓存/ │
│ 审计/版本  │    │ 限流/任务锁│

```

| 容器 | 技术 | 职责 | 状态性 | 故障影响 |
|---|---|---|---|---|
| Nginx | 1.24+ | 静态托管、TLS、反向代理、gzip/brotli | 无 | 全站不可访问 |
| 前端 SPA | Vue 3 + Vite | 页面渲染、路由守卫、交互 | 无（浏览器侧） | 页面空白，刷新可恢复 |
| 后端 | Spring Boot 3.2 | 业务规则、鉴权、审核、任务 | 无（会话在 Redis） | 接口 5xx，静态页仍可访问 |
| MySQL | 8.0 | 主数据、审核/审计/版本 | 有（唯一权威） | 读接口不可用 |
| Redis | 7 | 令牌、缓存、限流、锁 | 可重建 | 登录续期与缓存失效，见 §9 |
| 本地存储 | 磁盘卷 | 原图 / 缩略图 / 展示图 | 有 | 图片不可见，文字不受影响 |

## 4 组件视图（C4 · L3）

### 4.1 后端分层

```
请求
 ▼
[Filter / Interceptor]  traceId → 鉴权（JWT）→ 账号状态 → 角色解析 → 限流
 ▼
[Controller]  参数校验（Bean Validation）→ DTO 转换 → 统一响应封装
 ▼
[Application Service]  业务规则 / 状态机 / 事务边界 / 审计埋点
 ▼
[Domain Service]  跨实体不变量（如图片门槛、重提次数、先到先审）
 ▼
[Mapper]  MyBatis-Plus 单表 CRUD；复杂 SQL 走 XML
 ▼
MySQL / Redis / StorageService
```

横切组件挂在服务层之上，不侵入 Controller：

| 组件 | 实现位置 | 说明 |
|---|---|---|
| 鉴权 | `security` 包 | JWT 解析、角色判定、openid 白名单缓存 |
| 审计 | `audit` 包 + AOP | `@Audit(action, targetType)` 同事务写日志 |
| 限流 | `ratelimit` 包 | Redis 计数，超限返回 429 |
| 缓存 | `cache` 包 | 统一键规范，读穿 + 写失效 |
| 存储 | `storage` 包 | `StorageService` 接口，V1 `LocalStorage` |
| 消息 | `notification` 包 | 站内消息落库，读侧统计未读 |
| 任务 | `job` 包 | `@Scheduled` + Redis 锁，幂等 |

依赖规则（违反即评审拦截）：

1. Controller 只依赖本模块 Application Service，禁止直连 Mapper 或跨模块 Mapper。
2. 跨模块只调用对方 Application Service 的公开方法，禁止直接读改对方表。
3. 状态机迁移只允许在归属模块内发生；审核模块只能"请求迁移"，不能直接写状态列。
4. DTO 与实体分离；出参不得暴露 openid 全量、内部状态枚举以外的字段。
5. 事务只加在 Application Service 写方法；只读查询不开事务。

### 4.2 前端分层

```
views/            页面（38 页，按路由组织）
 ├─ layouts/      前台顶栏布局 / 后台侧栏布局
 ├─ components/   跨页组件（TeaCard、TeaImage、StatusBadge、FilterChipsBar…）
 ├─ modules/      按业务域的 API 封装与类型（catalog、submission、moderation…）
 ├─ stores/       Pinia：登录态、筛选态、对比篮、未读数
 ├─ router/       路由表 + 守卫（前台会员守卫 / 后台管理员守卫）
 └─ styles/       tokens.css（源自 DESIGN_SYSTEM）+ 页面样式
```

规则：

- 前台不引入第三方 UI 库；后台仅用 Element Plus（TECH_STACK §3.2）。
- 图片一律经 `TeaImage` 组件输出，内置 4:3、懒加载、失败占位与来源标注位。
- 登录态只存 access token 于内存 + refresh 于安全存储；页面跳转前校验，401 统一跳登录并记录回跳点。
- 筛选态不写入后端会话，由 URL query 复现；对比篮（≤3 款）由服务端按用户保存，Pinia 仅作前端缓存，保证 Web 与小程序一致（PRD §12.4）。
- 任何页面不得写死茶品数值（茶类数量、状态文案），一律来自接口或常量表。

## 6 关键流程

### 6.1 微信扫码登录与会话建立（M01）

| 步骤 | 动作 | 实现要点 |
|---|---|---|
| 1 | 前端请求登录二维码 | 后端生成一次性 `state`（Redis 5 分钟），返回二维码内容 |
| 2 | 用户微信扫码并授权 | 微信回调携带 `code` + `state` |
| 3 | 后端校验 state | 不存在或已用 → 拒绝并提示刷新（防重放） |
| 4 | `code2Session` 换 openid | 超时 3 秒；失败不建号（E11） |
| 5 | 查 openid → 建号或复用 | 首次建号拉取昵称头像；已注销 openid 已解绑则建新账号（E14） |
| 6 | 判定角色 | openid 命中白名单 → 管理员 / 超管；否则注册用户；缓存 60 秒 |
| 7 | 签发令牌 | access JWT 2 小时；refresh 7 天存 Redis，多设备独立 |
| 8 | 前端回跳 | 回到触发页并重放原操作（收藏/点赞/举报） |
| 9 | 每次请求校验 | JWT 签名 + 过期 + 账号状态（禁言/封禁/注销申请中按操作拦截） |
| 10 | 注销 | 二次确认 → 7 天冷静期 → 到期解绑 openid、内容匿名化、refresh 全清 |

约束：登录态不得写入 Cookie 之外的明文；refresh token 轮换；后台 `403` 页面与前台登录页分离，不暴露后台存在性（A01）。

### 6.2 茶品录入 → 提交审核 → 上架 / 下架（M02 + M08）

| 步骤 | 动作 | 服务端规则 |
|---|---|---|
| 1 | 管理员新建/编辑 | 必填：茶名、茶类、亚类、产地、状态；保存即草稿 |
| 2 | 自动保存（A04） | 60 秒节流，仅草稿态可写；带 `version` 乐观锁 |
| 3 | 提交审核 | 校验图片门槛：≥4 张才可提交；五维标签必填；锁定前台不可见 |
| 4 | 审核通过 | 管理员或超管可操作；二次确认；写审计（前后状态、理由） |
| 5 | 上架副作用 | 更新最后更新时间；空亚类自动转"正常"；失效列表/详情缓存 |
| 6 | 驳回 | 必填理由 ≥10 字；回到草稿，驳回理由在后台可见 |
| 7 | 下架 | 必填原因（管理员主动 / 投诉成立 / 纠错修订）；前台返回"内容已下架" |
| 8 | 恢复上架 | 必填恢复原因；写审计（E15） |

并发控制：同一茶品同时只允许一个待审核版本；编辑已上架条目产生"修订草稿"，前台继续展示已上架版本，审核通过后才切换（ADR-08）。

### 6.3 投稿 T1 / T3 / T4（M07 + M08）

| 步骤 | 动作 | 服务端规则 |
|---|---|---|
| 1 | 保存草稿 | 仅本人、仅草稿态；不占当日额度 |
| 2 | 提交 | 校验必填（T1 标题/正文 ≥300 字/关联茶品；T3 图片 1～5 张 + 授权；T4 字段/新值/理由 20～200 字） |
| 3 | 限额 | 每人每日 ≤3 条（Redis 日计数 + 数据库兜底，R-42） |
| 4 | 查重 | 茶名 + 茶类 + 亚类命中已有茶品 → 引导改纠错/补图（R-39） |
| 5 | 审核通过 | T1 落入品鉴区；T3 进入用户实拍相册（授权核验）；T4 生成修订版本 |
| 6 | 审核驳回 | 必填理由；重提次数 +1，达 2 次锁定（R-40） |
| 7 | 结果通知 | 站内消息（审核结果类），保留 180 天（R-52） |
| 8 | 并发纠错 | 同一茶品同一字段只允许一条待审核纠错，先到先审（R-44） |

### 6.4 图片上传与入图鉴（M03）

| 步骤 | 动作 | 服务端规则 |
|---|---|---|
| 1 | 前端预校验 | 扩展名 / 大小 ≤5MB / 4:3 提示（仅体验层） |
| 2 | 上传 | `multipart` 到 `/api/v1/admin/media` 或会员投稿接口 |
| 3 | 三重校验 | 扩展名 + MIME + 文件头；任一不符直接拒绝（E13） |
| 4 | 存储 | `tea/{teaId}/{type}-{seq}.{ext}`；`type ∈ dry/soup/leaf/pack` |
| 5 | 派生图 | 异步生成缩略图 640×480、展示图 1600×1200；失败进补偿任务 |
| 6 | 元数据 | 来源类型、权利人、授权范围、期限、凭证编号；缺凭证只能进草稿 |
| 7 | 直出 | Nginx `/uploads/` 只读；前端带来源标注 |

### 6.5 评论先审后发（M06 + M08）与举报治理（M08）

| 流程 | 关键约束 |
|---|---|
| 发布评论 | 登录 + 茶品已上架 + 账号正常（非禁言/注销申请中）；短评 + 单图；命中导流词（店铺名/微信号/链接）直接驳回 |
| 审核 | 待审核 → 通过（前台可见）/ 驳回（作者可见理由）；作者可删除不可编辑 |
| 举报 | 登录 + 三处入口（图片/评论/用户实拍）；同一用户对同一对象仅可举报一次 |
| 处理 | 48 小时内首次响应；成立则下架/删除 + 通知作者 + 审计；不成立则关闭并通知举报人 |
| 申诉 | 被处理方 1 次申诉，仅超管复核；撤销则恢复内容，保留原处理记录（E16） |

## 7 横切能力

### 7.1 鉴权与授权

| 层 | 机制 |
|---|---|
| 传输 | 全站 HTTPS；access token 走 `Authorization: Bearer`；refresh 仅用于续期 |
| 服务端 | 拦截器解析 → 角色（游客/用户/管理员/超管）→ 方法级 `@RequireRole` → 数据级归属校验（如 P20 仅本人） |
| 账号状态 | 禁言拦截评论/投稿；封禁拦截全部写操作与登录；注销申请中拦截评论/投稿/纠错/新增收藏 |
| 管理端 | openid 白名单（缓存 60 秒，变更即失效）；禁止操作自己账号；至少保留 1 名超管 |
| 前端 | 路由守卫 + 401/403 统一处理；不作为安全边界 |

### 7.2 审计

- 触发范围：审核通过/驳回、上下架/恢复、标签审核、白名单增删、禁言/封禁、投诉处理与申诉复核、批量导入、系统配置变更。
- 记录字段：操作人、角色、操作类型、对象类型与 ID、原因、变更前后状态、IP、时间。
- 写入方式：与业务同事务，业务失败则日志不落地；查询只读（A17），导出仅超管。
- 保留 180 天，按月归档后清理；修订历史单独保留（PRD 要求"仅后台可见"）。

### 7.3 限流

| 场景 | 维度 | 阈值（初值） | 超限表现 |
|---|---|---|---|
| 登录二维码/轮询 | IP | 10 次/分钟 | 429 + 提示稍后重试 |
| 投稿提交 | 用户 | 3 条/日（R-42） | 403 + 剩余额度提示 |
| 评论发布 | 用户 | 20 条/日 | 429 |
| 举报提交 | 用户 | 10 条/日 | 429 |
| 图片上传 | 用户 | 30 张/小时 | 429 |
| 公开读接口 | IP | 600 次/分钟 | 429（防爬） |

实现：Redis 固定窗口计数，键 `mm:{env}:rl:{scope}:{identity}:{window}`；Redis 故障时放行并记录告警（可用性优先）。

### 7.4 缓存

| 对象 | 键 | TTL | 失效 |
|---|---|---|---|
| 茶类/亚类/筛选项 | `mm:{env}:catalog:facets` | 10 分钟 | 茶品上架/下架/分类变更 |
| 茶品详情 | `mm:{env}:catalog:tea:{id}` | 10 分钟 | 该茶品任意写操作 |
| 首页精选 | `mm:{env}:catalog:featured` | 10 分钟 | 上架/下架 |
| 图鉴列表首页 | `mm:{env}:media:gallery:{tab}` | 5 分钟 | 新增采纳图 |
| 管理员角色 | `mm:{env}:auth:admin:{openid}` | 60 秒 | 白名单变更 |
| 未读数 | `mm:{env}:msg:unread:{userId}` | 1 分钟 | 消息创建/已读 |

原则：Redis 只存可重建数据；缓存不可用时直接读 MySQL；空值缓存 60 秒防穿透；批量失效按域前缀删除。

### 7.5 文件与存储

- `StorageService`：`store` / `delete` / `url` / `exists`；V1 本地实现，后续可替换对象存储而不改业务。
- 上传先落临时目录，校验与派生完成后原子移动，避免半成品直出。
- 孤儿文件（无 DB 记录）由周任务清理，保留 7 天宽限。
- 演示图不在上传目录，部署脚本显式排除 `docs/content/demo-images/` 与 `prototype/assets/img/tea/`。

### 7.6 消息与通知

- 站内消息落库，4 类：审核结果 / 纠错结果 / 投诉结果 / 系统通知；未读红点由计数缓存提供。
- 不接短信、不接微信模板消息（V1 边界）；审核结果只保证站内可见。
- 消息不可删除，180 天自动清理；清理前不做归档（业务可重建性低，按 PRD 直接清理）。

### 7.7 日志与追踪

- 入口生成 `X-Request-Id`（无则生成），写入 MDC，响应头原样返回，前端错误提示可展示该 ID。
- JSON 行日志：时间、级别、traceId、用户 ID（脱敏）、路径、耗时、错误码。
- 慢请求 >500ms 单独告警行；敏感字段（openid、令牌、AppSecret）不落日志。

### 7.8 错误码

- 结构：`MM-{域}-{三位}`，域 ∈ AUTH / CATALOG / MEDIA / SUB / GOV / SYS。
- HTTP 语义：400 参数、401 未登录、403 无权限/账号受限、404 不存在或已下架、409 冲突（重复举报/并发纠错）、429 限流、500 未预期。
- 前端按错误码映射文案，禁止直接展示服务端堆栈。

## 8 数据一致性与幂等

| 场景 | 手段 |
|---|---|
| 收藏 / 浏览历史 | 唯一键（用户, 茶品）；历史以 upsert 更新时间，超 50 条淘汰最旧 |
| 点赞 | 唯一键（用户, 评论）；计数异步汇总或读时聚合（第 3 轮定） |
| 举报重复 | 唯一键（举报人, 对象类型, 对象 ID）；重复提交返回 409 并沿用原记录 |
| 投稿日限额 | Redis 日计数（主）+ 数据库当日计数（兜底）；提交前双检 |
| 并发纠错 | 待审核纠错唯一约束（茶品 + 字段，仅待审核态生效），后到者驳回 |
| 审核并发 | 茶品/投稿带 `version` 乐观锁；审核动作要求状态仍为待审核，否则 409 |
| 跨模块副作用 | 领域事件在事务提交后处理（`AFTER_COMMIT`），失败写补偿表重试，最多 5 次并告警 |
| 缓存一致 | 先写库后删缓存；删除失败依赖 TTL 兜底；禁止"先删缓存后写库" |
| 图片与条目 | 图片记录与茶品同库；文件先落盘后写记录，删除反向（先标记后清理） |

V1 不引入分布式事务；跨模块最终一致可接受的范围仅限通知、缓存、缩略图、统计。

## 9 失败与降级策略

| 故障 | 影响 | 降级行为 | 恢复 |
|---|---|---|---|
| MySQL 不可用 | 所有读写失败 | 返回 503；Nginx 静态页仍可打开；健康检查转 DOWN | 重启容器；必要时从最近备份恢复 |
| Redis 不可用 | 登录续期、缓存、限流、任务锁受影响 | access token 仍可校验（无状态）；缓存直读库；限流放行并告警；定时任务暂停 | Redis 重启后缓存自动重建；任务锁自动释放 |
| 微信接口超时/失败 | 新登录失败 | 提示授权失败 + 重试；游客可继续浏览（E11） | 接口恢复后可重试，二维码可刷新 |
| 图片存储写入失败 | 上传失败 | 明确提示重试；已填表单不丢（E13）；其余功能正常 | 磁盘扩容或清理后重试 |
| 缩略图生成失败 | 列表图缺失 | 回退展示原图 + 占位；任务重试 | 补偿任务成功后替换 |
| 定时任务未执行 | 超时标记、注销到期、消息清理延迟 | 业务不受阻；超时标记由查询时兜底计算（按提交时间） | 下次调度补跑，任务幂等 |
| 备份失败 | 恢复能力下降 | 记录告警并写系统通知；不阻塞业务 | 次日重跑，保留策略不缩水 |
| 前端资源更新 | 用户拿到旧版本 | 静态资源带 hash；SPA 版本变更提示刷新 | 回滚上一版 dist |

原则：读优先于写；浏览优先于互动；审核类动作宁可失败也不"自动通过"（R-43）。

## 10 部署、发布与回滚

### 10.1 拓扑与卷

```
deploy/
├─ docker-compose.yml   # nginx / backend / mysql / redis
├─ nginx.conf           # /、/uploads/、/api/
├─ backup.sh            # mysqldump + uploads 增量，保留 7 份
└─ .env.example         # 数据库口令、微信 AppSecret、初始超管 openid
volumes: mysql-data / redis-data / uploads / logs
```

### 10.2 环境差异

| 项 | dev | test | prod |
|---|---|---|---|
| 启动方式 | Compose + 前端 Vite 代理 | Compose（构建产物） | Compose（构建产物） |
| 数据 | 本地样例（10 款） | 验收数据 | 正式数据 |
| 微信 | 测试号 | 测试号 | 正式资质 |
| 日志级别 | DEBUG | INFO | INFO/WARN |
| 备份 | 不启用 | 每日 | 每日 + 季度演练 |

### 10.3 发布步骤

1. 备份数据库与上传目录。
2. 构建前端 `vite build`、后端 fat jar、镜像。
3. 执行 Flyway 迁移（只前滚，失败即中止发布）。
4. 启动新容器，健康检查通过后切换 Nginx upstream。
5. 冒烟：首页、列表、详情、登录、后台登录、一次审核动作。

### 10.4 回滚

- 应用：回退上一镜像 tag，前端回退上一份 dist；数据库不回滚（迁移向前兼容）。
- 数据：仅当迁移造成不可逆损坏时，按备份恢复，需明确接受数据丢失窗口。
- 回滚动作本身写入运维记录，不写业务审计。

## 11 架构决策记录（ADR）

| 编号 | 决策 | 理由 | 代价 |
|---|---|---|---|
| ADR-01 | 单体分层，不拆微服务 | 100 并发、单机部署、单人运维；拆分会放大部署与联调成本 | 模块边界靠约定与评审维持 |
| ADR-02 | 前后台同一 SPA，路由前缀隔离 | 复用组件与请求层；后台入口仍独立 `/admin` | 需严格路由守卫与构建分包 |
| ADR-03 | JWT access + Redis refresh | 无密码体系；多设备在线；可主动失效 | 需要 Redis；刷新链路有状态 |
| ADR-04 | 本地磁盘 + `StorageService` 抽象 | 不启用商用 CDN（PRD §12.2）；后续可换对象存储 | 单机磁盘容量与备份压力 |
| ADR-05 | MySQL 结构化查询，不引 ES | 46 款规模；筛选维度均可建索引 | 检索能力上限低，扩展需重构 |
| ADR-06 | 站内消息落库，不接推送 | V1 只要求站内可见（R-52） | 用户需主动查看，触达弱 |
| ADR-07 | 事务内事件 + 提交后处理 + 补偿表 | 避免跨模块强耦合，又不丢副作用 | 需维护补偿任务与告警 |
| ADR-08 | 茶品"线上版本 + 修订草稿"双版本 | 支持已上架编辑与纠错修订留痕（R-45、PRD §10.1） | 查询需区分线上版本与草稿 |
| ADR-09 | 缩略图异步生成 | 上传响应快；失败可重试 | 列表首次可能短暂缺图 |
