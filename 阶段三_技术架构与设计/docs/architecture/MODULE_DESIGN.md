## 1 划分原则

| 原则 | 说明 |
|---|---|
| 按业务能力划分 | 模块对应稳定的业务域，不按页面切分；一个页面可由多个模块协作 |
| 单一归属 | 每类数据只有一个归属模块（owner），其他模块只能调用其服务，不能直接改表 |
| 状态机单点 | 状态迁移只在归属模块内实现；审核模块只发起"审核动作"，不直接写状态列 |
| 依赖单向 | 上层模块可依赖下层模块，禁止环形依赖；公共能力（M11）不依赖任何业务模块 |
| 页面可映射 | 38 页每页必须能落到一个主责模块，避免出现"无主页面" |
| 规模匹配 | 46 款茶品、100 并发，不拆微服务；模块边界靠包结构与评审约束 |

## 3 模块职责与边界

### M01 账号与会话

- 职责：微信授权登录、建号、令牌签发与刷新、角色判定（openid 白名单）、账号资料、注销冷静期、账号状态门禁、管理员白名单维护。
- 不负责：处罚的判定与记录（M08 发起，M01 只执行会话失效与登录拦截）；消息内容（M09）。
- 依赖：M11（缓存、限流、审计）。
- 核心实体：账号、管理员白名单、注销申请。
- 接口前缀：`/api/v1/auth`、`/api/v1/me/profile`、`/api/v1/me/overview`、`/api/v1/admin/admins`。
- 关键规则：无密码、无找回（R-46）；多设备在线（R-47）；注销 7 天冷静期与解绑（R-48、R-49）；至少保留 1 名超管（R-50）；openid 对外脱敏。

### M02 茶品与分类

- 职责：6 茶类 / 23 亚类 / 46 款茶品的结构与内容；茶品字段、别名、产区、冲泡参数、标准号、采摘期、生产年份与年份区间；上下架状态机；修订版本；空亚类状态；列表筛选与排序的查询编排。
- 不负责：图片文件与版权凭证（M03）；标签词表本身的增删审（M04）；审核动作的留痕编排（M08）；搜索相关度（M05）。
- 依赖：M04（标签）、M11（审计、缓存）。图鉴完整性由 M03 同步的就绪标记提供，不直接调用 M03。
- 核心实体：茶类、亚类、茶品、茶品别名、产区、冲泡参数、标准号、茶品修订版本、茶类-亚类标签关联。
- 接口前缀：`/api/v1/categories`、`/api/v1/teas`、`/api/v1/admin/teas`、`/api/v1/admin/categories`。
- 关键规则：每亚类 2 款（R-01）；等级缺失显示"未分档"且不参与等级筛选（R-05、R-66）；生产年份系统映射区间（R-64、R-65）；8 维筛选（R-61～R-63）；上架门槛读取出图鉴就绪标记（≥4 张）。

### M03 图鉴与媒体

- 职责：图片上传校验、存储路径、派生图、图鉴槽位与顺序、来源与版权凭证、用户实拍相册、图片举报对象引用。
- 不负责：T3 投稿的提交与审核状态（M07/M08）；茶品字段（M02）；前台页面布局。
- 依赖：M02（茶品归属与图鉴就绪标记同步）、M11（存储、审计）；T3 采纳结果经事件接收，不直接依赖 M07。
- 核心实体：图片、图片授权信息、图鉴槽位、用户实拍项。
- 接口前缀：`/api/v1/gallery`、`/api/v1/media`、`/api/v1/admin/media`。
- 关键规则：4～5 张可上架、2～3 张仅草稿（R-20）；顺序干茶→汤色→叶底→包装（R-22）；单图 ≤5MB（R-24）；缺凭证不得进正式图鉴（TECH_STACK §4）。

### M04 标签词表

- 职责：五维受控标签的维度、启停；新增标签的提交与审核；停用不删除；关联茶品数由 M02 提供只读统计，页面层组合展示。
- 不负责：茶品上选用哪些标签（M02 写入关联）；筛选 UI；关联计数计算。
- 依赖：M11（审计写入）。
- 核心实体：标签维度、标签、标签新增申请。
- 接口前缀：`/api/v1/tags`、`/api/v1/admin/tags`。
- 关键规则：运营不可自由新增（PRD §5.6）；驳回必填理由（R-55）；停用标签不出现在新选择项。

### M05 检索与自查

- 职责：关键词检索（茶名/别名/产地/工艺/品质特征/拼音）、相关度排序、无结果相近推荐、五维自查条件组合与候选输出。
- 不负责：茶品数据维护（M02）；不调用任何第三方识别服务（R-18）。
- 依赖：M02、M04。
- 核心实体：只读视图（无独立业务表）。
- 接口前缀：`/api/v1/search`、`/api/v1/identify`。
- 关键规则：仅结构化字段精确匹配（R-11、R-12）；别名命中展示正式名（R-13）；自查未选维度为"不限"，同维多选为"或"（R-16、R-17）。

### M06 用户互动

- 职责：收藏（想喝/已喝）、浏览历史（50 条）、对比数据装配、评论发布与作者删除、点赞。
- 不负责：评论审核判定（M08）；茶品内容；对比字段的业务口径（取 M02 发布版本）。
- 依赖：M02（茶品有效性）、M01（账号状态）、M11。
- 核心实体：收藏、浏览历史、对比篮、评论、评论点赞。
- 接口前缀：`/api/v1/me/favorites`、`/api/v1/me/history`、`/api/v1/me/compare`、`/api/v1/teas/{id}/comments`、`/api/v1/me/comments`。
- 关键规则：收藏上限 500（R-28）；分组固定（R-29）；历史去重保留最新（R-30）；对比 2～3 款且按用户持久化以支持双端一致（R-31、PRD §12.4）；评论短评 + 单图、无回复（R-33）；先审后发、可删不可改（R-34）；导流词拦截（R-35）。

### M07 投稿与修订

- 职责：T1/T3/T4 的草稿、提交、限额、查重、重提计数、锁定、通过后的落位编排（T1 品鉴区 / T3 实拍相册 / T4 修订版本）、预览快照。
- 不负责：审核判定与理由（M08）；图片存储（M03）；茶品版本落库（M02）。
- 依赖：M02、M03、M09（结果通知）、M11。
- 核心实体：投稿、投稿附件、字段差异、重提记录、预览快照。
- 接口前缀：`/api/v1/me/submissions`。
- 关键规则：T1 强制绑定茶品（R-37）；T3/T4 必填项（R-38）；按"茶名+茶类+亚类"查重（R-39）；驳回可重提 ≤2 次（R-40）；每日 3 条（R-42）；署名昵称/匿名（R-41）；并发纠错先到先审（R-44、R-45）。

### M08 审核与治理

- 职责：统一审核队列（茶品/投稿/评论）、审核动作编排、举报受理与处理、申诉复核、账号禁言/封禁、审计日志查询与导出（写入由 M11 承担）。
- 不负责：内容状态的实际迁移（由 M02/M06/M07 各自执行）；用户资料修改；消息发送内容（M09）。
- 依赖：M02、M06、M07、M01（处罚执行）、M09、M11。
- 核心实体：审核记录、举报、举报证据、处理记录、申诉、处罚记录；审计日志为只读视图。
- 接口前缀：`/api/v1/reports`、`/api/v1/admin/reviews`、`/api/v1/admin/reports`、`/api/v1/admin/users`、`/api/v1/admin/audit-logs`；资源级审核动作走 `/api/v1/admin/{teas|submissions|comments}/{id}/review`。
- 关键规则：审核工作日 24h 内完成、超时只标记不自动通过（R-43、E12）；驳回必填理由；举报 48h 首次响应、申诉 1 次（R-53）；投诉全字段留痕（R-54）；审计 180 天（R-51）；管理员不可处置自己。

### M09 站内消息

- 职责：4 类消息落库、未读计数、单条/全部已读、180 天清理、点击跳转目标定位。
- 不负责：邮件/短信/微信模板消息（V1 不做）；消息模板文案以外的业务判定。
- 依赖：M11；被 M01/M07/M08 调用。
- 核心实体：消息。
- 接口前缀：`/api/v1/me/messages`。
- 关键规则：用户不可删除（R-52）；未读红点；保留 180 天。

### M10 运营工具

- 职责：工作台待办聚合、批量导入（模板/校验/导入）、系统配置（只读项与可调项）、协议文案与版本。
- 不负责：茶品字段校验细则（M02 提供校验服务）；审核判定（M08）；分类结构本身（M02）。
- 依赖：M02、M07、M08、M01、M11。
- 核心实体：导入任务、导入错误行、系统配置、配置变更记录、协议文案。
- 接口前缀：`/api/v1/admin/dashboard`、`/api/v1/admin/imports`、`/api/v1/admin/settings`、`/api/v1/pages/about`。
- 关键规则：批量导入单批 ≤500 行（TECH_STACK §3.1）；"全部校验通过才允许导入"为当前实现口径，最终以 PRD §19 确认为准；只读配置项不得开放编辑。

### M11 平台公共能力

- 职责：统一响应与错误码、分页、鉴权拦截、限流、缓存、`StorageService`、审计埋点与写入、补偿任务、定时调度、日志与 traceId。
- 不负责：任何业务规则；不得反向依赖 M01–M10。
- 接口前缀：无对外业务接口（`/actuator/health` 仅运维）。

## 4 核心状态机

> 状态名严格沿用 PRD §10；`→` 表示允许迁移，括号内为前置条件。

### 4.1 茶品条目（归属 M02，审核动作由 M08 发起）

| 当前状态 | 事件 | 前置条件 | 目标状态 | 副作用 |
|---|---|---|---|---|
| 草稿 | 提交审核 | 必填齐全；图片 ≥4 张；五维标签齐全 | 待审核 | 锁定前台不可见；记录提交时间与提交人 |
| 草稿 | 删除 | 无待处理投稿引用 | —（物理/逻辑删除） | 审计留痕 |
| 待审核 | 审核通过 | 操作者为管理员或超管；状态仍为待审核 | 已上架 | 更新最后更新时间；空亚类转"正常"；失效缓存 |
| 待审核 | 审核驳回 | 理由 ≥10 字 | 草稿 | 记录驳回理由；清除超时标记 |
| 已上架 | 编辑 | 操作者为管理员 | 已上架（生成修订草稿） | 前台继续展示已上架版本（ADR-08） |
| 已上架 | 下架 | 原因必填（主动/投诉/纠错） | 已下架 | 前台不可见；写审计；后台保留下架原因 |
| 已下架 | 恢复上架 | 恢复原因必填 | 已上架 | 缓存失效；写审计（E15） |
| 已下架 | 编辑 | 操作者为管理员 | 已下架（生成修订草稿） | 修订通过后仍需手动恢复上架 |

约束：

- 同一茶品同一时刻最多 1 个待审核版本；修订草稿与原版本互不覆盖。
- 已上架条目"编辑"不直接改前台字段；修订审核通过后才切换发布版本，并保留历史（R-45）。
- 下架无自动过期；恢复必须人工（PRD §10.1）。
