## 1 目标与范围

### 1.1 质量目标

| 目标 | 判定口径 |
|---|---|
| 功能完整 | PRD §6 的 13 组功能与 38 页规格均有对应用例并通过 |
| 状态正确 | 茶品、投稿、评论、举报、申诉、账号 6 组状态机的合法/非法迁移全部覆盖 |
| 权限可靠 | 四类角色 × 接口组的权限矩阵逐格验证，越权用例 100% 拒绝 |
| 数据一致 | 双端（Web/小程序接口）收藏、历史、对比、账号状态同源 |
| 性能达标 | 首屏 ≤2 秒；100 并发下接口 P95 ≤300ms（TECH_STACK §9） |
| 安全可控 | [SECURITY](../architecture/SECURITY.md) §14 的 10 项验收全部通过 |
| 可回归 | 核心链路 Playwright 用例可在任意环境重复执行 |

### 1.2 范围内

- 前台 P01～P20 与后台 A01～A18 的接口、状态、交互与空态。
- M01～M11 十一个模块的 service、mapper、controller。
- 微信授权登录（测试号）、图片上传、批量导入、审核与治理、站内消息。
- 弱网/离线降级、浏览器兼容、基础安全与性能。

### 1.3 范围外

- 小程序原生 UI（仅验证与 Web 共用接口的兼容性）。
- 二期功能：购买跳转、AI 自动识茶、全文检索、社交、产区地图等（PRD §16.1）。
- 支付、商品、第三方登录（V1 不存在）。
- 正式渗透测试与等保测评；仅执行 SECURITY §14 自检。
- 生产数据迁移与容量规划（另立专项）。

## 6 状态机覆盖

| 状态机 | 合法迁移 | 非法迁移用例 |
|---|---|---|
| 茶品 | `draft → pending → published → offline → published`；`pending → draft` | `draft → published` 直接发布拒绝 |
| 投稿 | `draft → pending → approved/rejected`；`rejected → pending`；第 2 次 `rejected → locked` | `locked → pending` 拒绝 |
| T4 修订 | `approved → revised` | 未通过直接 `revised` 拒绝 |
| 评论 | `pending → published/rejected`；`published → deleted` | `rejected → published` 拒绝 |
| 举报 | `pending → processing → resolved_valid/resolved_invalid` | 重复处理 409 |
| 申诉 | `pending → upheld/overturned` | 第 2 次申诉拒绝 |
| 账号 | `active → deleting → active/deleted`；`active → muted/banned → active` | `deleted → active` 拒绝 |
| 图片 | 草稿态 → 随条目上架 → 随条目下架 | 缺凭证直接上架拒绝 |

- 每个非法迁移必须返回 `MM-CATALOG-002` / `MM-SUB-004` 或对应 409，且不产生副作用。
