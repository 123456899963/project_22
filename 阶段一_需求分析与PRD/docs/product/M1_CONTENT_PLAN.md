## 1 目的与结论

本方案同时推进两件事：

1. 对 PRD §19 的 5 项待确认事项给出可执行建议，减少进入工程化前的悬空决策。
2. 给出 M1「10 款样例上线」的具体茶品清单、每款图片素材清单、授权凭证清单与字段核校清单，作为内容准备与 M1 验收的直接依据。

当前事实基础（2026-11-06 实测）：

- 原型数据共 46 款、6 茶类、23 亚类；结构化字段无缺失（名称、产地、采摘、标准号、描述、冲泡 5 项、更新时间均齐备）。
- 46 款图片均为接口生成的示意图，只能用于版式演示，**不可用于上线**；上线素材需按本方案重新采集与授权。
- 10 款样例的选择不改变 46 款总量与亚类结构，仅决定首批素材与核校的优先级。

## 2 PRD §19 五项待确认事项：建议

### 2.1 事项 1：10 款样例茶品清单

建议采用第 3 节的 10 款清单。选择原则：

- 覆盖全部 6 个茶类，保证首页、分类、搜索、详情四条主路径都有真实内容。
- 覆盖关键验收分支：无年份、未分档、多等级、4 图与 5 图、新茶/中期茶/老茶三种年份区间。
- 优先辨识度高、资料易核校、素材易获取的品类，降低首款上线风险。
- 保留 2 款云南与湖南黑茶，保证「黑茶」不是空壳分类。

### 2.2 事项 2：批量导入校验规则

建议规则如下（与原型 A12「全部通过才可导入」保持一致）：

| 维度 | 建议规则 |
|---|---|
| 模板字段 | `name`、`alias`、`py`、`cat`、`sub`、`origin`、`grade`、`year`、`pick`、`std`、`desc`、`temp`、`ratio`、`vessel`、`seconds`、`times`、`aroma`、`ferment`、`updated` |
| 必填 | `name`、`cat`、`sub`、`origin`、`pick`、`std`、`desc`、`temp`、`ratio`、`vessel`、`seconds`、`updated` |
| 枚举校验 | `cat` 必须为 6 茶类之一；`sub` 必须属于所选茶类；`grade` 仅允许「特级 / 一级 / 二级 / 未分档」；`year` 为 4 位年份或空；`times` 为正整数 |
| 格式校验 | `std` 多个标准号用分号分隔；`grade` 多档用斜杠或顿号分隔；日期统一 `YYYY-MM-DD` |
| 查重 | 以「茶名 + 茶类 + 亚类」为唯一键，命中即标红该行并禁止导入 |
| 错误处理 | 校验阶段逐行隔离，展示行号、字段与原因，提供错误明细 CSV；全部行通过后「确认导入」才可用 |
| 执行失败 | 导入执行阶段若发生非校验类错误，整批回滚并写审计；校验通过后的业务拒绝不算执行失败 |
| 图片 | Excel 只导入文字字段，不导入图片；新条目默认 `draft`，图鉴不足 4 张不得上架 |
| 审计 | 记录导入人、文件名、总行数、成功行数、失败行数与失败原因摘要 |

### 2.3 事项 3：成功度量指标目标值

以下为首版建议值，需运营确认后写入 PRD §16.3：

| 指标 | 建议目标值 | 口径说明 |
|---|---|---|
| 检索命中率 | ≥ 85% | 有结果搜索次数 / 总搜索次数 |
| 搜索无结果率 | ≤ 10% | 无结果搜索次数 / 总搜索次数 |
| 审核 24h 达成率 | ≥ 90% | 工作日 24h 内完成审核数 / 总审核数 |
| 投稿通过率 | 40%～60% | 通过投稿数 / 提交投稿数 |
| 图鉴完整率 | 100% | 已上架条目中图片达 4 张的比例 |
| 自查候选命中率 | ≥ 60% | 自查后进入详情次数 / 自查总次数 |
| 收藏 7 日留存率 | ≥ 20% | 7 日内再次访问的收藏用户 / 收藏用户 |

### 2.4 事项 4：M0–M3 日期与准入门槛

日期需业务方确定，本方案只给顺序与出口标准，便于排期时直接套用：

| 里程碑 | 出口标准（满足才可进入下一阶段） |
|---|---|
| M0 工程与后台基础能力 | 真实微信授权登录与账号体系可用；后台录入、审核、上下架状态流转可用；权限与审计日志落库；备份与恢复演练通过 |
| M1 10 款样例上线 | 第 3 节 10 款全部满足：≥4 张已授权图鉴、字段核校完成、可被茶名/别名/拼音检索、详情年份分支正确 |
| M2 首批 22 款上线 | 绿茶、红茶、青茶全部上线；分类计数与筛选无空亚类异常 |
| M3 全量 46 款上线 | 白茶、黄茶、黑茶补齐；批量导入在真实数据上跑通并通过 A12 验收 |

推进顺序建议：M0 与内容准备并行；内容先按 M1 清单交付，再按 M2 → M3 分批扩量。任何素材未取得授权的茶品不得进入对应批次。

### 2.5 事项 5：隐私政策、用户协议与运营主体

上线前必须补齐以下信息，P19 现有文案只作为内容骨架：

| 类别 | 必须明确的内容 |
|---|---|
| 运营主体 | 公司全称、统一社会信用代码、注册地址、联系方式与隐私事务邮箱 |
| 收集范围 | 微信 openid、昵称、头像；收藏、历史、投稿、评论、举报；必要的访问日志 |
| 使用目的 | 建号与身份识别、内容审核、消息通知、安全与合规 |
| 存储与期限 | 站内消息与审计日志 180 天；注销冷静期 7 天；到期解绑与匿名化规则 |
| 第三方 | 微信开放平台、图片存储/CDN、日志与备份服务商清单及各自用途 |
| 用户权利 | 查询、更正、删除、撤回授权、注销的入口与处理时限 |
| 协议条款 | 内容规范、版权授权、违规处理、申诉 1 次、免责声明 |
| 合规手续 | ICP 备案、公安备案、隐私政策生效日期与版本号 |

建议由法务按上述清单出正式文本，替换 P19 摘要版；运营主体信息未确定前，不对外发布正式版协议。

## 5 字段核校清单

原型字段完整不等于内容准确。M1 每款需由编辑按下列顺序核校并留痕：

| 字段 | 核校要点 | 依据 |
|---|---|---|
| 茶名 / 别名 / 拼音 | 与标准或权威资料一致；别名不重复、不误导 | 国家标准、产区公开资料 |
| 茶类 / 亚类 | 分类归属正确；普洱归入黑茶、白茶按 4 花色 | PRD §2 分类规则 |
| 产地 | 写到产区层级，不写店铺或品牌 | 国家标准、地理标志文件 |
| 等级 | 仅「特级 / 一级 / 二级 / 未分档」；无分档证据时用未分档 | PRD 字段字典 |
| 生产年份 | 4 位年份或空；无可靠来源不填 | 包装标识、检测报告 |
| 采摘时间 | 用展示词，与月份区间一致 | 标准或产区资料 |
| 标准号 | 多值分号分隔；仅保留可核查的现行标准 | 国家标准全文 |
| 冲泡参数 | 水温、茶水比、器皿、出汤时间、次数 5 项齐全且互相匹配 | 标准或产区推荐 |
| 品质描述 | 只写可观察特征，不写功效与绝对化结论 | PRD 内容规范 |
| 更新时间 | 本次核校日期 | 内容流程 |

核校完成后，逐款记录「核校人、核校日期、依据清单、改动摘要」，作为 M1 验收附件。
